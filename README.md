# notification-hub

Одно уведомление можно разослать по всем открытым вкладкам пользователя. Текст остаётся в базе, в браузер он уходит потоком SSE: обычный HTTP, клиент только читает.

У каждого соединения своя очередь на 50 сообщений. Если вкладка зависла и не разбирает поток, новые сообщения для неё выбрасываются. Отправка при этом не встаёт.

Лимит — сколько уведомлений пользователь может получить за минуту. Окно скользящее, значение `RATE_LIMIT_PER_MINUTE` (по умолчанию 30). Сверх лимита `POST` отвечает 429. И лимит, и подписчики живут в памяти процесса: после рестарта поток надо открыть заново, история в Postgres на месте. Второй экземпляр API про чужие соединения не знает.

Кто знает `user_id`, тот и читает его поток. Логина нет.

## Запуск

```bash
docker compose up --build
```

http://localhost:8003/docs

```bash
python -m venv .venv
.venv/Scripts/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
```

Сначала слушаем, потом пишем. В первом терминале:

```bash
curl -N localhost:8003/users/1/stream
```

Во втором:

```bash
curl -X POST localhost:8003/users -H "Content-Type: application/json" -d '{"username": "vasya"}'
curl -X POST localhost:8003/users/1/notifications \
  -H "Content-Type: application/json" -d '{"message": "привет из второго терминала"}'
```

Пока уведомлений нет, в потоке раз в 15 секунд приходит heartbeat, иначе прокси рвёт тихое соединение.

История: `GET /users/1/notifications`, последние 50. Флага «прочитано» нет, только факт, что сообщение приняли или упёрлись в лимит.

```bash
pytest -v
```
